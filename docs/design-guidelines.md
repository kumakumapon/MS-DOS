# KDESK と KGUI32 のデスクトップ設計

## 配色と寸法

- 余白は 4・8・16 ドットを単位にする。角は直角とし、KGUI32 のタイトル面は 28 ドットを使う。新しい主操作のボタンは高さ 36 ドットとし、既存の密なレイアウトはアプリごとに調整する。
- 共通パレットのアクセントは濃青 `#3366AA`、選択中の印は琥珀 `#FFBB66`。面・境界・文字・無効・成功・危険の配色は `tools/desktop-style.h` に置く。
- キーボードで移動した操作対象には 2 ドットの枠を付ける。タスクバーではアクティブ項目に高さ 2 ドットの下線を付ける。
- 基準は 8×16 ドットの文字セル。見出しやボタンの幅は Shift-JIS のバイト数で確認し、全角文字を途中で切らない。

## 操作部品

- 主操作は淡青のボタンで示し、副操作は通常色で統一する。上書きや破棄などは危険色とし、結果が分かる説明と取消しの導線を設ける。
- KGUI32 SDK では `kw_draw_button` が主・副・危険の色とフォーカス・無効・押下の状態を扱う。無効な操作の領域はポインタからの入力を受け付けない。共通の入力欄・スクロールバー・確認ダイアログも同じ配色を使う。
- `kg_button` は従来の副操作色で描画する。SDK の役割付きボタンは既存の RGB フィールドとコントロール ID を使う。アプリメニューと Editor・Images の確認操作でこの描画経路を使用する。
- アイコンは 16・32 ドットの格子を基準に文字と併記する。タップで押せる導線を用意し、右クリックに依存しない。ショートカットはボタンと重ならない案内欄に置く。

## 確認

- 部品の描画は PEGC 640×400 と Cirrus 800×600 で確認する。フォーカス枠の太さと無効操作のヒット領域は、ホスト側で実際のクライアント描画要求を検証する。
- 画面の上下をシステム操作とタスクバーに確保する。起動時の Welcome と System は、640×400 と 800×600 の作業領域に影ごと収める。KGUI32 の描画とクリック判定は同じランチャー矩形を使う。
- UI の定型ラベルは共通の `tools/kgui32/ui/strings.tsv` から Shift-JIS に変換する。起動時の設定ファイルは `KUMAUI.CFG` とし、先頭行が `JA` のとき日本語を選ぶ。

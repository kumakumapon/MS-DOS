# KGUI32 independent protected-mode desktop

現在のタップ操作・アプリ拡充は [WINDOW-MENU.md](WINDOW-MENU.md) を参照してください。

KGUI32 is an original PC-98 desktop foundation. Its GUI executes in 32-bit
protected mode without starting KDESK. KDESK and the original MS-DOS kernel
remain available. Welcome/System share the desktop with two owned DOS/PM32
text-session windows. Window composition, focus, resizing, viewport scrolling
and input routing execute in the CPL3 GUI. The first graphical-client SDK and separate calculator/clock EXEs are
available through the Welcome launcher. See [CLIENT-SDK.md](CLIENT-SDK.md)
and [SESSIONS.md](SESSIONS.md) for the client and text-session contracts.
Graphical Japanese text and Editor Shift-JIS reading/writing are described in
[JAPANESE.md](JAPANESE.md). Editor includes an app-local Japanese IME: F4
toggles input, F5 switches Romaji/JIS kana, Space converts, Enter commits.
V86 DOS windows also render private Japanese TVRAM and PC-98 text attributes;
see [TERMINAL.md](TERMINAL.md) for output, cursor, snapshots and diagnostics.

## Build and run

With GNU make, GCC supporting `-m16`/`-m32`, binutils and Python 3:

```
make -C tools/k386 all
make -C tools/k38632 all test
make -C tools/kgui32 all test
```

On a 386+ PC-98 with an XMS driver, enabled IRQ0 and no active protected-mode
owner, load `K386.EXE`, then `K32HOST.EXE`, then `KGUILDR.EXE`. Put
`KGUI32.EXE`, `KSH.EXE` and the loaders on A:. The normal webnp2 distribution
loads Calculator, Clock, Files, Editor, COUNT32 and ARGS32 from the verified
HDD APPS directory; the explicit full-FD choice keeps those applications on A:.
See [HDD-APPS.md](HDD-APPS.md) and the
[standalone HDD boot profile](../../ports/pc98/hdd/BOOT.md). Use 16 MiB extended memory in
WebNP2. A separate optional image is generated by WebNP2; normal KDESK images
and saved disks are not replaced. PEGC uses 640×400 indexed 256 colours;
Cirrus uses 800×600 RGB565 (65,536 colours).

Welcome has a two-column app launcher and a Shortcuts button. F1 opens or
closes its key guide. Tap Components in the guide or press G to see the shared
button states and icon sizes. F8 switches the desktop language for the current
run. Desktop notices report launch failures, app faults and CPU test results.
They clear after four seconds or when tapped.
Use `ECHO JA>A:\KUMAUI.CFG` before starting the desktop to begin in Japanese;
`KGUILDR KGUI32.EXE ja` selects Japanese for an explicit launch.
See the [desktop guidelines](../../docs/design-guidelines.md).

Drag a title bar to move a window. Tab changes focus; arrow keys move built-in
windows and are forwarded to focused PM32 sessions. The taskbar restores
minimized windows. **New DOS 1/2** opens KSH in a free slot or restores an
existing window. Session controls: Run (Ctrl+L), Stop (Ctrl+P), Resume (Ctrl+R),
End (Ctrl+E), Again (restart the last successfully loaded root command).
End a live root before Run; type, for example, `COUNT32.EXE 1` or
`VIEW32.EXE VIEWDATA.TXT` and press Enter. Escape cancels the command editor.
Run can replace an ended/faulted root. An unsuccessful load leaves its prior
generation and screen intact. Closing a session ends its owned root;
minimizing only hides it, and background execution continues.

The bottom-right grip resizes session windows. Left/Right/Up/Down buttons
scroll their canonical 80x25 screen without reflow. Cursor following after
keyboard input keeps shell prompts visible. Text is ASCII, 8x16; the viewport
may clip rows/columns at PEGC resolution. Tab and Ctrl+L/P/R/E are reserved
by the desktop. Ctrl+C interrupts the session (V86 child returns to its
parent); normal letters including Q/T/S reach the focused app. F10 or Exit
to DOS always ends the desktop. Escape/Q also exit from built-in windows.
At the DOS prompt, type `KDESK` for the existing environment.

System / Test CPU (T, when a built-in is focused) starts two diagnostic
COUNT32 workers if both slots are free. System Stop (S) ends loader-owned
workers, including interactive sessions. Foreign live/faulted tasks are
visible through New DOS but cannot receive keys/control or be replaced;
GUI exit never ends another owner's generation.

## Architecture and service boundary

`desktop.c` and `scene.c` form the CPL3 GUI. They own the framebuffer, damage
packing, all pixel composition, fonts, cursor, window geometry and input hit
testing. The application has its own 4 MiB XMS-backed address space, GDT/IDT/TSS,
page tables, CPU frame and stacks. Code and argument pages are read-only,
the stack has an unmapped guard and low memory remains supervisor-only.

`KGUILDR.EXE` is a separate DOS allocation with a trusted real-mode broker.
It instantiates `k38632/host-engine.S`, the **same** bounded CPU engine used by
K32HOST, rather than adding another copy or changing the old two-slot ABI.
It schedules the existing app manager only after returning to real mode, never
from a DOS IRQ or while a graphics bank is being copied. Its transient
graphical callback is restored on cleanup and consumes neither app slot. CPU IRQ0 preemption lets native
F10/Escape stop even an uncooperative GUI loop.

The common PM32 services stay compatible. Only the GUI loader accepts feature
bit 16 and calls 64–72; ordinary K32RUN/K32HOST reject GUI packages. Register
convention matches `k32_call`: EAX service, EBX pointer/action, ECX byte count;
EAX returns a result or negative error. Structures use fixed unsigned 32-bit
fields from `gui.h`:

| Call | Contract |
| --- | --- |
| 64 INFO | Copy a 96-byte versioned GuiInfo to writable user memory. |
| 65 EVENT | Copy one 48-byte GuiEvent, return 1; return 0 when none is ready. |
| 66 PRESENT | Read a 24-byte GuiPresent, validate rectangle/pitch/entire readable source range, copy packed rows and present damage. |
| 67 FONT | Copy the original 95×16-byte ASCII table, or read one validated CG-ROM glyph through a 48-byte GuiGlyph request. See JAPANESE.md. |
| 68 PROOF | Action 1 starts two diagnostic workers, 2 stops loader-owned generations. |
| 69 SESSION | Read a 152-byte versioned command; validate slot, operation, generation and ownership before touching the monitor. |
| 70 SNAPSHOT | Read a versioned header and copy a 2080-byte session view including an 80x25 screen to writable user memory. |
| 71 CLIENT VIEW | Copy an owned graphical frame and its actual generation/token to writable desktop memory. |
| 72 CLIENT EVENT | Post a bounded input/resize event to the matching owned generation/token. |

Native drivers expose no user I/O privilege or direct VRAM mapping. PRESENT
copies through a private 32 KiB conventional scratch block into existing
PEGC/Cirrus drivers. There is one bounded call per dirty rectangle, no
per-pixel trap. Font/palette caches, scratch and page tables are released on
exit or fault. The 32-event input queue coalesces motion and counts overflow;
the native hardware queue preserves the latest button release. DOS file
operations stay serialized and read-only.

The 256-byte `KG32DRV1` debugger producer references the actual CPU engine
record. The CPU samples the GUI's first 64 writable bytes while its mapping
is active. These samples describe real executed state, not ELF metadata.
Reclaimed records are postmortem evidence in freed DOS memory, not a resident
API or a substitute for resource queries.

## Verification and limits

`make test` exercises geometry, clipping, odd-coordinate final releases,
focus/minimize/reopen, explicit GUI package acceptance/rejection and stack
bounds. WebNP2 `scripts/verify-kgui32.mjs` tests both video devices with actual
CPU frames, page tables, RAM samples, pixels, input and full FAT12 hashes.

`KGPROOF.COM` is a DOS-side test parent. It creates two COUNT32 owners before
four child GUI launches, verifies continued progress with unchanged
generations/CR3/backing/heaps, then ends its own workers. It queries actual
XMS free/largest blocks and conventional free memory to prove reclamation.
`KGUILDR KGUI32.EXE badapi`, `fault` and `spin` are negative test modes;
`sessionapi` rejects malformed/stale requests and foreign-owner control.
`once` and `proof` exit automatically. Do not use fault/spin modes for work.

The GUI is an experimental protected desktop client with two built-ins and
two text-session windows. The native loop alternates bounded execution and
real-mode drivers; it is not a permanently protected-mode kernel or a new
MS-DOS implementation. The initial graphical SDK supports one retained canvas per client and
rectangle/text/button commands. Advanced DOS hardware modes and additional execution slots remain later work.
SDK2/3/4 provide Files, guest clipboard and the ASCII editor; see the SDK links below. Existing KDESK retains those features. No Windows APIs, resources or
binaries are used. An EMM386/V86 owner is incompatible with this loader;
the optional image uses the existing standalone XMS driver instead.


The launcher also includes **Files**, with read-only root and Work TXT preview,
and selection-to-Editor launch; see [Files / Editor integration](FILES-EDITOR.md).
In Work, choose **Manage** for folders, sorting, copy, move, rename, and Trash.
[Work management and boot settings](STANDARD-APPS.md) also covers **Memo** (F4),
the System task list, and **Settings** (F9).
See [GUI SDK 2 / Files](BROWSER-SDK.md) for the original read-only browser.

SDK3 adds the temporary editor and reusable picker; see [EDITOR-SDK.md](EDITOR-SDK.md) for lifecycle, keyboard and clipboard contracts.

SDK4 adds bounded workspace saves and a common Save As dialog; see [SAVE-SDK.md](SAVE-SDK.md).
The optional workspace information operation routes those calls to the verified

### デスクトップとファイル管理

- 上部の **Kuma** からシステム情報、設定、DOS、アプリ検索、ウィンドウ切替、DOSへの終了を開けます。検索は Ctrl+K またはメニューから開き、アプリ名や実行ファイル名で絞り込めます。F2 は Welcome を開きます。
- Alt+Tab で一覧を表示し、Alt を離すと選択したウィンドウへ切り替わります。PC-98のキー名は GRPH+Tab です。同じ一覧をKumaメニューから開いてタップでも切り替えられます。
- 専用HDDの Work に Welcome／System とアプリごとの位置・大きさ・スナップ状態を保存します。同じアプリを開いたときに画面内へ収めて復元します。ファイルと実行中のアプリの再開はそれぞれのアプリから操作します。
- Files の **Drives** で左のパネルを開き、Work、A:、認識済みの対応HDDを直接選べます。Ctrl+Dでも開けます。「システム表示」で保護項目を一覧に表示できます。パンくずはタップ、またはTabとEnterで上位へ戻れます。ドライブ直下は読み取り専用で、ファイル操作はWorkにあります。フォルダのコピーは192項目、1ファイル1 MiB、合計8 MiB、Workから3階層までです。宛先と同じ親にTMPを作り、成功時に公開します。中止・失敗時は原本とTMPを保持します。フォルダの移動は同じ親の中では名前変更を使い、親をまたぐ場合はコピー後に元のフォルダをごみ箱から復元できる状態にします。
- EditorとImagesは共通のファイル選択画面を使います。Imagesは Ctrl+O でBMPを開き、Ctrl+Shift+SでWorkへの名前付き保存を選べます。画像の上書き確認と原本保持は引き続き有効です。
- Settingsの **Desktop preferences** で標準／高コントラスト、日本語／英語、IMEオフ／ローマ字／JISかなを選べます。表示と言語は保存後に適用し、IMEの既定値は次に開くEditorとUser dictionaryが読み込みます。

### デスクトップと起動

- Settings の **Desktop preferences → Desktop and startup** で壁紙（グラデーション・単色・格子）、PC-98 JIS／US記号配列、相対マウスの速度（標準・半速・倍速）、日付・時刻形式、起動時のアプリを選べます。上部バー、Filesの更新日時、Clockに地域設定が反映されます。webnp2の画面タップは設定値にかかわらず絶対座標で動きます。
- 設定は Work の `KGUIPREF.DAT` に保存します。旧形式を読み込むと追加項目には既定値が入ります。起動時のアプリは次回のデスクトップ起動時に開きます。
- 上部バーにはフォーカス中のEditorまたはUser dictionaryのIME状態（`*` は入力中、`+` は候補選択中）、空きXMS容量、webnp2の出力音量（ミュート時は0%、通常時は100%）が出ます。対応する音量情報が取得できない環境では `Vol --` と表示します。同じ実行ファイルのウィンドウは下部バーの1ボタンにまとまり、押すたびに切り替わります。Alt+Tabからも個別に選べます。
- Editor・Images・Settingsの保存とFilesのコピーは、完了・失敗を下部に短く通知します。FilesのコピーとTXT復旧プレビュー、Imagesの大きいBMPの読込は、共通の進捗表示から「中止」またはEscで取り消せます。フォルダの中断ではTMPを確認・復旧できます。ファイルの書込み確定は既存のTMP/BAK処理を使います。
- ネイティブ診断 `KGPERF01` は ARTIC の307,200 Hzカウンターでローダー開始から最初の描画完了まで、ダメージ領域の描画時間と面積、取り込んだキー・左ボタンから次の描画完了までを記録します。webnp2のE2EはHDD起動から最初のデスクトップ描画とEditorの入力応答も計測します。

### 最近使った項目とファイル操作

- Kumaメニュー（Ctrl+Shift+K）の「最近」でアプリとTXT／BMPを開けます。「固定」または Ctrl+P で文書を先頭に表示できます。固定は4件までです。「除外」またはDeleteで選んだ履歴を消し、文書は媒体に残します。FilesでWorkの文書や親フォルダを移動・改名すると、履歴が新しいパスへ移り、固定を引き継ぎます。対応HDDにアプリ履歴とWorkの最大10件の文書を保存します。読取専用ドライブの文書履歴は起動中に保持します。
- FD・HDDの表示は、Workや共通ダイアログがDOSのファイルブローカーを使ったときに点灯します。Alt+矢印で配置・最大化・復元、Alt+F4で閉じます。再起動では未保存のアプリを順に確認します。
- 大きい文字は、ランチャー、Editor本文、共通ダイアログ、Files、Clockの時刻、Calculatorの結果、Calendar、Imagesのファイル名、ユーザー辞書、設定に適用します。Calculator・Clock・Calendar・ユーザー辞書は Tab／Shift+Tab で項目を移動し、Enterで実行できます。Calendarの大きい表示はウィンドウに収まる週を表示し、Page Down または「週を送る」で続きを開きます。
- Filesの「TMP」からサブフォルダに入り、最大1 MiBのShift-JIS TXTやBMPを読み取り専用で確認できます。TXTはPage Up／Downでページ送りし、Ctrl+Fまたは「検索」で文字列を探せます。「Recover」でTMPフォルダ全体を空いている別名へ復旧します。
- 大きい文字はDOS端末のテキスト表示とアプリメニューにも反映します。DOS端末ではCtrl+Tabで操作ボタンにフォーカスし、Tab／Shift+Tabで移動してEnterで実行します。Escで端末の入力に戻れます。アプリメニューでもTab／Shift+Tabで操作項目を移動できます。
- Imagesの Ctrl+C／Ctrl+V は同じKGUI32セッションで最大128×128のRGB565を共有します。KDESKとの共有では、Imagesの Ctrl+B／Ctrl+J と、KDESK画像ウィンドウの「Share」「Get」を使います。対応HDDの `WORK/KGCLIP.BMP` に最大256×192のRGB565相当の色をBMP24で保持します。PEGCでの表示にはパレットを使います。
- Editorのメニューまたは Ctrl+Shift+B／Ctrl+Shift+J と、KDESKのText Editorの「Share」「Get」（Ctrl+B／Ctrl+J）で、対応HDDの `WORK/KGTEXT.TXT` にShift-JISの文字列を最大1,024バイト共有できます。KGUI32は選択範囲か文書全体を共有し、KDESKは文書全体を共有します。

# KGUI32 independent protected-mode desktop

KGUI32 is an original PC-98 desktop foundation. Its GUI executes in 32-bit
protected mode without starting KDESK. KDESK and the original MS-DOS kernel
remain available. This first milestone provides Welcome and System windows,
software cursor, damage-based composition, title-bar dragging, keyboard focus,
minimize/close/taskbar restore and clean DOS return. External DOS/application
windows and a general widget SDK are **not implemented** in this desktop yet.

## Build and run

With GNU make, GCC supporting `-m16`/`-m32`, binutils and Python 3:

```
make -C tools/k386 all
make -C tools/k38632 all test
make -C tools/kgui32 all test
```

On a 386+ PC-98 with an XMS driver, enabled IRQ0 and no active protected-mode
owner, load `K386.EXE`, then `K32HOST.EXE`, then `KGUILDR.EXE`. Put
`KGUI32.EXE`, `COUNT32.EXE` and the loader on A:. Use 16 MiB extended memory in
WebNP2. A separate optional image is generated by WebNP2; normal KDESK images
and saved disks are not replaced. PEGC uses 640×400 indexed 256 colours;
Cirrus uses 800×600 RGB565 (65,536 colours).

Drag a title bar to move a window. Tab changes focus; arrow keys move the
focused window. The taskbar restores a minimized or closed built-in window.
F10, Escape, Q or Exit to DOS ends the desktop. At the DOS prompt, type
`KDESK` for the existing environment.

System / Test CPU (T) starts two diagnostic COUNT32 workers only if both app
slots are free. Stop (S) ends only workers started by this loader. These are
execution/ownership diagnostics, not general application windows. GUI keys
are not delivered to these workers. A normal, waiting or stopped existing
owner makes Test CPU return busy; no existing owner is replaced or killed.

## Architecture and service boundary

`desktop.c` and `scene.c` form the CPL3 GUI. They own the framebuffer, damage
packing, all pixel composition, fonts, cursor, window geometry and input hit
testing. The application has its own 4 MiB XMS-backed address space, GDT/IDT/TSS,
page tables, CPU frame and stacks. Code and argument pages are read-only,
the stack has an unmapped guard and low memory remains supervisor-only.

`KGUILDR.EXE` is a separate DOS allocation with a trusted real-mode broker.
It instantiates `k38632/host-engine.S`, the **same** bounded CPU engine used by
K32HOST, rather than adding another copy or changing the old two-slot ABI.
It schedules the existing app manager only after returning to real mode, never
from a DOS IRQ or while a graphics bank is being copied. It has no persistent
interrupt hook and consumes neither app slot. CPU IRQ0 preemption lets native
F10/Escape stop even an uncooperative GUI loop.

The common PM32 services stay compatible. Only the GUI loader accepts feature
bit 16 and calls 64–68; ordinary K32RUN/K32HOST reject GUI packages. Register
convention matches `k32_call`: EAX service, EBX pointer/action, ECX byte count;
EAX returns a result or negative error. Structures use fixed unsigned 32-bit
fields from `gui.h`:

| Call | Contract |
| --- | --- |
| 64 INFO | Copy a 96-byte versioned GuiInfo to writable user memory. |
| 65 EVENT | Copy one 48-byte GuiEvent, return 1; return 0 when none is ready. |
| 66 PRESENT | Read a 24-byte GuiPresent, validate rectangle/pitch/entire readable source range, copy packed rows and present damage. |
| 67 FONT | Copy 95×16 bytes of PC-98 CGROM ASCII glyphs to writable user memory. |
| 68 PROOF | Action 1 starts two diagnostic workers, 2 stops loader-owned generations. |

Native drivers expose no user I/O privilege or direct VRAM mapping. PRESENT
copies through a private 32 KiB conventional scratch block into existing
PEGC/Cirrus drivers. There is one bounded call per dirty rectangle, no
per-pixel trap. Font/palette caches, scratch and page tables are released on
exit or fault. The 32-event input queue coalesces motion and counts overflow;
the native hardware queue preserves the latest button release. DOS file
operations stay serialized and read-only.

The 256-byte `KG32DRV1` debugger producer references the actual CPU engine
record. The CPU samples the GUI's first 64 writable bytes while its mapping
is active. These samples describe real executed state, not ELF metadata.
Reclaimed records are postmortem evidence in freed DOS memory, not a resident
API or a substitute for resource queries.

## Verification and limits

`make test` exercises geometry, clipping, odd-coordinate final releases,
focus/minimize/reopen, explicit GUI package acceptance/rejection and stack
bounds. WebNP2 `scripts/verify-kgui32.mjs` tests both video devices with actual
CPU frames, page tables, RAM samples, pixels, input and full FAT12 hashes.

`KGPROOF.COM` is a DOS-side test parent. It creates two COUNT32 owners before
three child GUI launches, verifies continued progress with unchanged
generations/CR3/backing/heaps, then ends its own workers. It queries actual
XMS free/largest blocks and conventional free memory to prove reclamation.
`KGUILDR KGUI32.EXE badapi`, `fault` and `spin` are negative test modes;
`once` and `proof` exit automatically. Do not use fault/spin modes for work.

The GUI is an experimental single protected desktop client with two built-in
windows. The native service loop alternates bounded execution and real-mode
drivers; it is not a permanently protected-mode kernel or a new MS-DOS
implementation. It has no arbitrary external GUI clients, resize widgets,
app/DOS window embedding, clipboard, file manager or Japanese text rendering
yet. Existing KDESK retains those features. No Windows APIs, resources or
binaries are used. An EMM386/V86 owner is incompatible with this loader;
the optional image uses the existing standalone XMS driver instead.
